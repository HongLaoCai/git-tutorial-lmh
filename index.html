Giới thiệu

Git là gì?

Git là hệ thống quản lý phiên bản (Version Control). Mỗi lần lưu có chủ đích gọi là commit — Git ghi lại ai đổi gì, lúc nào, và vì sao.

Lịch sử đầy đủ

Quay lại bất kỳ mốc đã commit. Không phụ thuộc vào “bản cuối cùng trên máy”.

Làm việc song song

Mỗi tính năng một nhánh (branch). Team không ghi đè code của nhau khi đang làm dở.

Phối hợp qua remote

Đẩy lên GitLab / GitHub để review, merge request, và backup ngoài máy cá nhân.

Ghi nhớGit chạy trên máy bạn. GitLab là máy chủ lưu repo từ xa — hai thứ khác nhau.

Giới thiệu

Ba khái niệm cần thuộc

Repository

Kho chứa toàn bộ file và lịch sử. Local = trên máy. Remote = trên GitLab.

Commit

Một mốc lưu có message và mã hash. Commit xong mới “chốt” thay đổi vào lịch sử.

Branch

Một dòng phát triển độc lập. main là nhánh chuẩn; tính năng mới làm trên nhánh riêng.

Giới thiệu

Thay đổi đi từ máy lên remote như thế nào

Luôn đi theo bốn bước này. Sai bước là nguyên nhân của hầu hết lỗi pull / push.

01 Working

File đang sửa trên máy, chưa đưa vào Git.

02 Staging

Chọn file sẽ nằm trong commit tiếp theo.

git add
03 Local repo

Lưu thành một commit trên máy.

Chiều ngược lạigit fetch chỉ tải thông tin mới. git pull tải rồi hợp nhất vào nhánh hiện tại.

Phần A · Bước 2

Tạo token PAT

PAT (Personal Access Token) dùng để xác thực Git qua HTTPS trên terminal.

  • Tạo token trên GitLab → Access Tokens.
  • Copy token một lần và lưu an toàn — GitLab không hiện lại.

Lưu ýĐăng nhập Git trên trình duyệt cũng xác thực và lưu thông tin trên máy. PAT dành cho thao tác trên terminal.

glpat-xxxxxxxxxxxxxxxxxxxx

Phần A · SSH

Dùng SSH keys

Ngoài PAT, có thể xác thực GitLab bằng SSH.

1. Xem danh sách key trên máy

ls -la ~/.ssh

2. Tạo SSH key mới

ssh-keygen -t ed25519 -C "your.email@example.com"

PassphraseKhi tạo key có thể đặt mật khẩu — cần nhớ để dùng lại.

3. Xem nội dung key công khai

cat ~/.ssh/id_ed25519.pub

Copy nội dung file .pub, dán vào GitLab → SSH Keys.

4. macOS hỏi passphrase nhiều lần

ssh-add --apple-use-keychain ~/.ssh/id_ed25519

Phần A · Clone repo

Clone repo và gắn PAT vào remote

Clone bằng HTTPS kèm username + PAT, rồi set remote để lần sau không nhập lại.

1. Clone repo

git clone https://USERNAME:glpat-xxxxxxxx@gitlab.com/group/studybooks-2026

2. Gắn PAT vào remote

git remote set-url origin https://USERNAME:glpat-xxxxxxxx@gitlab.com/group/studybooks-2026.git

3. Kiểm tra

origin  https://USERNAME:glpat-xxxxxxxxxx@gitlab.com/group/studybooks-2026.git (fetch)
origin  https://USERNAME:glpat-xxxxxxxxxx@gitlab.com/group/studybooks-2026.git (push)

Bảo mậtKhông đưa token thật lên slide, chat hay commit. Token trong remote URL nằm plaintext trên máy.

Phần B · Lệnh thường dùng

git fetch là gì?

git fetchTải thông tin, dữ liệu và lịch sử mới nhất từ remote về máy — không merge, không đổi code đang làm.

git fetch

Công thứcgit pull = git fetch + git merge

Phần B · Lệnh thường dùng

Bộ lệnh dùng hàng ngày

Thuộc vòng lặp này trước khi xử lý tình huống nâng cao.

git pull
git fetch
git add .
git status
git commit -m "commit"
git push origin main

git branch -a
git branch
git checkout
  • git status — xem đang có thay đổi gì
  • git add . — đưa thay đổi vào staging
  • git commit -m "…" — lưu thành một commit
  • git push origin main — đẩy lên remote nhánh main
  • git branch / git branch -a — xem nhánh local / tất cả
  • git checkout — chuyển nhánh (kèm tên nhánh)

Phần B · Branch

Tạo branch mới

Cách 1 — Tạo và chuyển sang nhánh mới

git checkout -b ten-branch-moi
git switch -c ten-branch-moi

Cách 2 — Chỉ tạo, vẫn đứng ở nhánh hiện tại

git branch ten-branch-moi

Phần B · Merge

Merge về branch và cherry-pick

Merge

  1. 1

    Checkout nhánh đích

    Đứng đúng nhánh muốn nhận code trước khi merge.

  2. 2

    Fetch (nếu cần) rồi merge

    Cùng trên local thì không cần fetch.

    git fetch
git merge branch_can_lay_code

Cherry-pick — lấy đúng một commit

git cherry-pick 67b17f1367b3e3c6e857f5beda196e8e2116e914

Phần B · Conflict

Xử lý conflict khi merge

Khi merge có nhiều conflict, chọn code theo từng phía rồi commit.

Giữ code của nhánh hiện tại

git checkout --ours .

Giữ code của nhánh đang merge vào (theirs)

git checkout --theirs .

Sửa từng file rồi commit

git add tenfile.abc
git commit -m "fix-conflict-tenfile.abc"

Hoặc sửa hết rồi commit một lần:

git add .
git commit -m "fix-conflict-new-branch"

Tình huống 2

Code xong quên tạo branch

Tình huống

Đang ở main, đã code hoặc đã commit, muốn tách sang nhánh mới để làm merge request.

a. Chưa commit

Tạo và chuyển sang nhánh mới, rồi tiếp tục.

git checkout -b feature-moi
git switch -c feature-moi

NhớPhải add và commit. Nếu không, khi quay lại main thay đổi vẫn còn trong working tree.

b. Đã commit — chưa push

Lùi commit gần nhất, rồi tạo nhánh như mục a.

git reset HEAD~1

c. Đã push

Vẫn dùng git reset HEAD~1 nếu commit đó chưa được merge.

Tình huống 3

Pull không được vì có commit local

Tình huống

Có 1 commit cần push, và 2 commit trên remote cần pull.

a. Chưa commit

Stash thay đổi, pull, rồi lấy lại.

git stash
git pull
git stash pop

b. Đã commit

Reset để lấy lại code, stash, pull, rồi stash pop. Fix conflict nếu có.

git reset HEAD~1
git stash
git pull
git stash pop

Tình huống 4 · Chưa commit

Muốn bỏ các thay đổi

Tình huống

Đang làm tính năng mới, muốn hoàn tác vài file về trạng thái đã commit.

Discard trên UI hoặc bằng lệnh

git restore tenfile.abc

# hoặc
git checkout tenfile.abc

Tình huống 4 · Đã commit

Lấy lại nội dung file từ commit hoặc nhánh

Dùng git reset HEAD~1 nếu chỉ cần lùi commit gần nhất, rồi discard file.

Nhiều commit — xem danh sách

git log --oneline

Lấy file từ một commit cụ thể (ví dụ 4b6bd5d):

git checkout 4b6bd5d -- tenfile.abc

Lấy file đúng như trên nhánh main:

git checkout main -- tenfile.abc

Tình huống 5

Commit thiếu file

Tình huống

Commit xong chưa push, nhớ ra thiếu thay đổi — muốn gộp vào commit vừa tạo.

a. Amend

Sửa file, rồi:

git commit --amend --no-edit

b. Reset rồi commit lại

git reset HEAD~1
git add .
git commit -m "commit"

Quy trình nàyKhông dùng rebase.

Tình huống 6

Lỡ commit file phải nằm trong .gitignore

Ví dụ

File .env, dump database, hoặc file nhạy cảm khác.

a. Chưa push

Reset, loại file khỏi staging, thêm vào .gitignore, rồi commit lại.

git reset HEAD~1
# loại file nhạy cảm khỏi staging
# thêm vào .gitignore
git add .
git commit -m "commit"

b. Đã push — cần xóa khỏi lịch sử

git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch .env" \
  --prune-empty --tag-name-filter cat -- --all
git add .
git commit -m "remove file .env from git"
git push origin main --force

Cẩn thậnpush --force ghi đè lịch sử trên remote. Chỉ dùng khi hiểu rõ và team đồng ý.

Tình huống 7

Quay lại commit cũ

Tình huống

Đã đi từ commit A sang commit B và đã push. Muốn về A để làm lại.

a. Reset theo số commit

Ví dụ 4b6bd5d cách HEAD 3 commit:

git log --oneline
git reset HEAD~3

b. Reset cứng về đúng commit, rồi force push

git reset --hard 4b6bd5d

# nếu B là commit vừa tạo:
git reset --hard HEAD~1

git push origin main --force

Cẩn thậnreset --hard xóa thay đổi chưa commit. push --force ghi đè remote.

Tình huống 7 · An toàn hơn

Dùng revert thay vì xóa lịch sử

Revert tạo commit mới đảo ngược thay đổi — lịch sử trên remote vẫn còn.

Revert commit B

git revert <ma_commit_B>

Sau đó tiếp tục làm và push như bình thường.

Khi nào chọn gìNhánh riêng, chưa ai dựa vào: có thể reset. Nhánh dùng chung: ưu tiên revert.

Tình huống 8

MR bị conflict — không merge vào main được

Luồng: kéo main → merge vào nhánh của bạn → sửa conflict → push nhánh đó.

  1. 1

    Pull main về

  2. 2

    Merge main vào nhánh của bạn

  3. 3

    Sửa conflict

  4. 4

    Push nhánh feature, không phải main

git checkout main
git pull origin main
git checkout ten_branch
git merge main

git add .
git commit -m "fix conflict"
git push origin ten_branch

Chú ýPush ten_branch, không phải main.

Tình huống 9

dev nhiều tính năng — chỉ merge một phần vào main

Tình huống

Repo có dev và main. Chỉ được đưa một số tính năng từ dev sang main.

Tạo nhánh mới từ main, checkout sang nhánh đó, rồi chọn một trong hai cách:

C1 — Cherry-pick

Lấy đúng commit của tính năng đó.

git cherry-pick <ma_commit>

C2 — Merge nhánh tính năng

Merge cả nhánh chứa tính năng cần lấy.

git merge branch_tinh_nang

Tình huống 10

Sửa commit message vừa gõ

Tình huống

Gõ sai chính tả trong message của commit vừa tạo, chưa push.

C1 — Reset rồi commit lại

git reset HEAD~1
git add .
git commit -m "tên commit đúng"

C2 — Amend message

git commit --amend -m "tên commit mới"
