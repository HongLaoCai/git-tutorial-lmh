Nhóm 1 · Xác thực

Tạo Personal Access Token

  • GitLab → Preferences → Access Tokens
  • Scope tối thiểu: read_repository / write_repository
  • Copy token một lần — mất là phải tạo lại

Không dán token thật lên slide / chat / commit

# Ví dụ placeholder (GIẢ)
glpat-xxxxxxxxxxxxxxxxxxxx
Nếu đã lộ token thật → revoke ngay trên GitLab.

Nhóm 1 · SSH

Xem & tạo SSH key

ls -la ~/.ssh

ssh-keygen -t ed25519 -C "ban@example.com"
  • Có thể đặt passphrase — nhớ passphrase
  • File private: id_ed25519 · public: id_ed25519.pub

Không bao giờ commit hoặc gửi file private key

Nhóm 1 · SSH

Đưa public key lên GitLab

cat ~/.ssh/id_ed25519.pub
# Copy → GitLab → SSH Keys → Add key

# macOS: nhớ passphrase trong Keychain
ssh-add --apple-use-keychain ~/.ssh/id_ed25519

Khi bị hỏi passphrase nhiều lần → dùng ssh-add như trên.

Nhóm 2 · Lệnh nền

fetch không đổi code của bạn

  • git fetch — tải lịch sử remote, working tree giữ nguyên
  • git pull = fetch + merge
git fetch origin
git status
git pull origin main

Nhóm 2 · Lệnh nền

Vòng lặp mỗi ngày

git status
git add .
git commit -m "mô tả thay đổi"
git push origin main

git branch -a
git branch
git switch ten-branch

Luôn status trước khi add / commit / push.

Nhóm 2 · Branch

Tạo / chuyển branch

Tạo và chuyển luôn

git switch -c feature-moi
# hoặc
git checkout -b feature-moi

Chỉ tạo, đứng yên

git branch feature-moi

Nhóm 2 · Merge

Merge & cherry-pick

  • Checkout nhánh đích (nhánh muốn nhận code)
  • git merge branch_nguon
  • Hoặc lấy đúng 1 commit: cherry-pick
git fetch
git merge feature-moi

git cherry-pick 67b17f1367b3e3c6e857f5beda196e8e2116e914

Nhóm 2 · Conflict

Xử lý conflict khi merge

  • --ours = nhánh đang đứng
  • --theirs = nhánh đang được merge vào
# Giữ toàn bộ theo nhánh hiện tại / phía kia
git checkout --ours .
git checkout --theirs .

# Sửa từng file → add → commit
git add tenfile.abc
git commit -m "fix-conflict-tenfile.abc"
# hoặc
git add .
git commit -m "fix-conflict-new-branch"
Đứng trên feature, merge main → ours=feature, theirs=main. Dễ nhầm.

Tình huống 2

Code xong quên tạo branch

a. Chưa commit

git switch -c feature-moi
# tiếp tục code → add → commit

Changes chưa commit đi theo bạn khi đổi branch (trừ khi conflict với branch đích).

Nhắc: quên add/commit rồi quay main → vẫn thấy trong changes.

Tình huống 2

Đã commit trên main — giữ commit trên branch mới

Thứ tự quan trọng

# b. Đã commit, chưa push
git branch feature-moi      # giữ commit trên branch mới
git reset --hard HEAD~1     # main lùi lại
git switch feature-moi

# c. Đã push — chỉ reset nếu chưa merge MR
# Cần force push → hỏi team trước

Reset trước khi tạo branch → commit có thể mất khỏi mọi nhánh.

Tình huống 3

Pull không được vì có commit local

a. Chưa commit

git stash
git pull
git stash pop
# fix conflict nếu có

b. Đã commit

# Cách gọn, ít mất commit
git pull --rebase origin main

Ưu tiên rebase thay vì reset lung tung

Tình huống 4

Bỏ changes chưa muốn giữ

# a. Chưa commit — một file
git restore tenfile.abc
# hoặc
git checkout -- tenfile.abc

# b. Lấy lại nội dung từ commit / branch khác
git log --oneline
git checkout 4b6bd5d -- tenfile.abc
git checkout main -- tenfile.abc

Tình huống 5

Commit thiếu file

Chỉ amend khi chưa push (hoặc chắc không ai pull)

# a. Amend
git add .
git commit --amend --no-edit

# b. Reset mềm rồi commit lại
git reset HEAD~1
# sửa file
git add .
git commit -m "commit đầy đủ"

Tình huống 6

Lỡ commit file phải ignore

a. Chưa push

git reset HEAD~1
# discard / bỏ stage file nhạy cảm
echo ".env" >> .gitignore
git add .
git commit -m "bỏ .env, cập nhật gitignore"

Đã push secret → revoke/rotate secret ngay

Xóa khỏi history: dùng git filter-repo (không dùng filter-branch cũ), rồi force push có kiểm soát.

Tình huống 7

Quay lại commit cũ

An toàn

git revert <ma_commit_B>
git push

Giữ lịch sử, tạo commit đảo ngược.

Phá hủy

git reset --hard 4b6bd5d
git push origin main --force

Xóa history trên remote — chỉ khi team đồng ý.

git checkout 4b6bd5d → detached HEAD. Làm tiếp: git switch -c hotfix-tu-A.

Tình huống 8

MR bị conflict — không merge vào main

git switch main
git pull origin main
git switch ten_branch
git merge main
# sửa conflict
git add .
git commit -m "fix conflict với main"
git push origin ten_branch

Push feature branch, không phải main

Tình huống 9

dev nhiều tính năng — chỉ merge một phần vào main

  1. Tạo branch mới từ main
  2. C1: cherry-pick đúng commit tính năng
  3. C2: merge nhánh feature nhỏ (không merge cả dev)
  4. C3: copy thủ công từng file (cuối cùng)
git switch main
git pull
git switch -c release-partial
git cherry-pick <sha-tinh-nang>

Tình huống 10 · 12 · 13

Sửa message · đổi tên · xóa branch

# Sửa message commit vừa tạo (chưa push)
git commit --amend -m "tên commit mới"

# Đổi tên branch hiện tại
git branch -m ten-branch-moi

# Xóa branch local
git branch -D ten-branch-muon-xoa

Cheat sheet

git statusXem trạng thái
git switch -c …Tạo + chuyển branch
git fetchTải remote, không merge
git pull --rebaseKéo + xếp commit local
git stash / stash popCất tạm changes
git restore fileBỏ sửa chưa commit
git commit --amendSửa commit cuối (chưa push)
git revert <sha>Đảo commit an toàn

An toàn

Đỏ / vàng — nhớ trước khi gõ

Nguy hiểm

  • push --force lên main
  • reset --hard khi chưa backup
  • Rewrite history đã share

Cẩn thận

  • PAT trong remote URL
  • amend sau khi đã push
  • Commit .env / dump DB

FAQ

Câu hỏi thường gặp

Detached HEAD?

Đang đứng trên commit, không phải tên branch. Tạo branch: git switch -c tên.

stash vs commit?

stash = tạm, local. Commit = lưu vào lịch sử branch.

ours / theirs?

ours = nhánh đang đứng. theirs = nhánh đang merge vào.

SSH hay PAT?

Máy mình → SSH. CI / script tạm → PAT (scope hẹp, hết hạn).
